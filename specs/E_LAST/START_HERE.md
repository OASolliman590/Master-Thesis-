# E_LAST — optional experimental integration, implemented last

**This is a separate specification, not a mandatory final stage of E core.** It can remain dormant forever without invalidating a completed public-data paper. It has its own activation, input, model-version, validation and publication contracts.

## Activation requires all of these

1. An accepted scientific E-core release: E0–E7 completed under C-SCHEDULING or C-IDENTIFIABILITY, with exact model, public-data, code, environment, figure and uncertainty receipts. A ZIP/specification or passing schema test is not that release.
2. Generated original measurements with known identity/events/biological units, permissions, QC and a permitted analysis role. A proposed assay or ordered reagent is not data.
3. An approved task-specific mapping from available observations to the frozen model context. Different drugs, cells, recognition mechanisms or assays need a new adaptation decision.
4. The integrator closes the core production lane and explicitly releases the selected X packet. Implement E_LAST scientific adapters only then. Laboratory recordkeeping and approved experiments may run in parallel; this rule delays computational integration, not lawful data collection.

Read `ACTIVATION_AND_DEPENDENCIES.md`, `DATA_CAPABILITIES_AND_ALL_OUTCOMES.md`, `DATA_CONTRACT_AND_GOVERNANCE.md`, then `CODEX_IMPLEMENTATION_PROMPT.md`. Every module is conditional on its actual data capability; there is no all-assays-mandatory default.

No numerical likelihood of obtaining a data type or positive biological effect is assigned. The 'all outcomes' matrix defines logical branches for availability/quality/compatibility/independence/outcome, and can combine multiple conditions. Unknown states fail closed for the affected module.
