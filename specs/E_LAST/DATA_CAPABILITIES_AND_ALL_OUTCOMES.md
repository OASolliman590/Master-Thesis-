# Capability and outcome matrix

Assess availability, quality, compatibility, independence and observed result separately. A positive sign is never an admission criterion; absence of data and an observed null effect are different states. Apply every relevant row, not just the first convenient one. The machine capability snapshot enumerates flags; unlisted/unknown combinations default to a review block for the affected module.

## Combinatorial rule

First apply permission/identity/QC/core gates. Then derive enabled modules from independent capabilities. Then assign development/evaluation roles. Finally interpret the result sign/precision. These axes combine: for example S07+S16+S18 permits nominal-exposure recovery modelling in one donor/context, not population-wide prospective efficacy validation.

No numerical 'probability of success' is populated. Empirical future success probabilities are UNKNOWN. Model-conditional prediction probabilities require a defined probability distribution and are not probabilities that a future data collection will succeed.
