Problem. Real files have no way in: records come only from demo.py or the synthetic legacy bridge, and source bytes are passed as a hex blob of at most 2 MB, which cannot hold a Riaz FPKM file.

Solution. Add one ingestion module. It reads verified objects by their sha256 from a local store. GEO-SOFT and author-table adapters inside it turn the bytes plus a declared field map into entity rows, each carrying its source locator. This is where audit_metadata.py and batchqual's riaz_fpkm and readers get ported.

  • Real data reaches registries
  • Two adapters justify the seam
  • Tests use small real-format fixtures
  • New cohort = new field map, not new code

Problem. The code mixes two questions in one field: where the data came from ("synthetic") and whether the checks passed ("ready"). The answer is hard-coded across about 13 modules, so real data is refused by construction.

Solution. Core declares the allowed classifications once, along with a ready status that says nothing about the data's origin. Stages pass the classification through instead of writing it themselves.

Problem. The admission draft is always "blocked" and matrices refuses anything that isn't blocked, so no source can ever be admitted.

Solution. Admission writes a worksheet listing only the judgment calls, each with pointers to its evidence. It reads the signed worksheet back and emits the draft. Matrices asks a single question: which sources are eligible for this branch?

  • Human judges, never transcribes
  • Real admission becomes possible
  • Round-trip tests: complete, partial, contradicted

E · Validate records once, at registries

Worth exploring in-process

Before: the same checks repeated

After
registries validates once; entity immutability is guaranteed

Problem. Downstream stages repeat checks registries already made, and core re-hashes the code on every verify. On real data volumes that becomes slow and noisy.

Solution. Registries becomes the only validator. Later stages rely on the immutability check that already exists, and dependency checks are cached for the duration of a run.

  • Faster real runs
  • Invariant tests live in one place

Speculative mock / fixture

Problem. Unit tests read docs/validation receipts, ARTIFACT_HASHES files and private functions. A refactor then fails on receipt bookkeeping rather than on behaviour, and that is exactly how the review loops kept going.

Solution. Unit tests go only through module interfaces. Checks on the receipts and evidence files move to a separate suite that runs only when asked.

  • A refactor stops breaking receipt tests
  • Tests check behaviour, not bookkeeping
