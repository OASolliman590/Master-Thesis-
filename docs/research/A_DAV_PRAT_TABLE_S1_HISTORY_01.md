## Findings

The article is the 2017 *Cancer Research* paper, volume 77, issue 13, pages 3540–3550; PubMed gives online publication on 9 May 2017 and issue publication on 1 July 2017 ([PubMed record](https://pubmed.ncbi.nlm.nih.gov/28487385/); [AACR article record](https://aacrjournals.org/cancerres/article/77/13/3540/619915/Immune-Related-Gene-Expression-Profiling-After-PD)). AACR’s article record says the supplementary data were available at “Cancer Research Online.” In this bounded check, that publisher record did not expose a resolvable 2017 file-level URL or a retrievable original attachment. Therefore the actual original 2017 file locator remains **unidentified**; the general publisher supplement reference is the only locator established here.

The current AACR Figshare record identifies a dataset titled “Table S1 from Immune-Related Gene Expression Profiling…” and says it was posted on 31 March 2023. It links the record as a supplement to the article DOI ([AACR Figshare item page](https://aacr.figshare.com/articles/dataset/Table_S1_from_Immune-Related_Gene_Expression_Profiling_After_PD-1_Blockade_in_Non_Small_Cell_Lung_Carcinoma_Head_and_Neck_Squamous_Cell_Carcinoma_and_Melanoma/22415270); [official item metadata API](https://api.figshare.com/v2/articles/22415270)). The captured public API representation reports item ID `22415270`, version `1`, item DOI `10.1158/0008-5472.22415270.v1`, resource DOI `10.1158/0008-5472.CAN-16-3556`, creation and publication timestamps of 31 March 2023, and a `modified_date` of 2 June 2023. It lists file ID `39861317`, filename `00085472can163556-sup-176636_2_unknown_upload_3997093_ddtlnx.xls`, and the public download route [ndownloader.figshare.com/files/39861317](https://ndownloader.figshare.com/files/39861317). These values were read from the official metadata response captured for the earlier public retrieval; the raw response and byte inventory remain in restricted temporary scratch, not this repository.

Figshare’s official API documentation defines public endpoints for listing article versions and retrieving a specified version ([API v2 documentation](https://docs.figshare.com/v2/)). The public list request, [GET `/v2/articles/22415270/versions`](https://api.figshare.com/v2/articles/22415270/versions), returned HTTP 200 and one entry: version 1, with its version-detail URL. The corresponding [version-detail request](https://api.figshare.com/v2/articles/22415270/versions/1) and the current-item request also returned HTTP 200 and identify version 1. Thus, the retrieved public Figshare version list contains one version at the time of capture. This does not establish whether an earlier attachment existed outside Figshare, or whether any unlisted, withdrawn, private, or pre-repository history exists.

The item’s 2023 Figshare association is evidence of the present repository linkage and dates, not evidence of when or why it was deposited. AACR’s current editorial policy describes automatic Figshare publication of supplementary items as a service ([AACR editorial policies](https://aacrjournals.org/pages/editorial-policies)); that general policy does not establish the handling of this specific 2017 attachment, a migration date, or identity between the historical and current bytes. The current page and API do not provide a 2017 attachment hash or a comparison against an independently located 2017 file. Byte continuity is therefore **not proven**.

The article page displays a Crossmark “Check for Updates” indicator, but this check did not retrieve an item-specific Crossmark event response. The bounded PubMed and publisher search did not identify a separate correction record. This is a limited search result, not proof that no correction or supplement change exists. No specific AACR migration announcement or item-specific explanation for the 2023 Figshare date was located.

## Closure statement

The actual 2017 file-level locator is still unknown. The current public file locator is the AACR Figshare item/file route above. The documented public version-list API returned exactly one entry, version 1, and the current item and version-detail records identify that version. This closes the gap about the accessible public Figshare version list as retrieved on 24 October 2026. It does not establish that the Figshare item was the first location of the attachment, nor that the current XLS is byte-identical to a file originally attached in 2017. It also does not explain the 2023 posting or rule out history before or outside the accessible Figshare record. No claim that the 2023 record is a migration or correction is warranted without an item owner’s record or a located 2017 attachment that can be compared. The remaining uncertainty is documentary and does not change any frozen endpoint, cohort, or analysis decision.
