# Riaz baseline RNA-seq QC proposal — 26 Oct 2026

**Status: proposed for reviewer decision; not applied.** Scope is `GSE91061 × A_BASELINE_BIO`, pretreatment specimens only, using author best overall response (BOR) as the response source of record. This note proposes deterministic metadata, assay-structure, and numeric-validity rules. It does not change a frozen specification, sign a worksheet, admit the cohort, inspect expression values, execute a matrix check, or run biological analysis.

## What is inherited and what is proposed

The approved endpoint contract maps CR/PR to objective response, SD/PD to objective nonresponse, and NE/unknown to not evaluable. Raw outcome labels stay intact and disagreements stay visible. The assay and processed-data contracts require exact source-object provenance, compatible measurement representation, unambiguous row/column identities, duplicate checks, numeric validity, documented units/transforms, feature identity, and branch-specific suitability. The baseline matrix contract requires one eligible patient row per branch, an outcome-independent specimen rule, reason-coded exclusions, and no build from an unadmitted source. These are inherited requirements, not new Riaz-specific policy. [Endpoint ontology](../../specs/A_DATA_ACQUISITION_VALIDATION/ENDPOINT_ONTOLOGY.md), [assay and measurement contract](../../specs/A_DATA_ACQUISITION_VALIDATION/ASSAY_AND_MEASUREMENT_CONTRACT.md), [processed-data policy](../../specs/A_DATA_ACQUISITION_VALIDATION/PROCESSED_DATA_POLICY.md), [patient-matrix contract](../../specs/A_DATA_ACQUISITION_VALIDATION/PATIENT_MATRIX_CONTRACT.md).

The Riaz-specific pass, block, and quarantine rules below are proposals for approval. The evidence reviews report 51 source-supported baseline specimen-to-patient joins; this is the retained metadata baseline set, not an analytical denominator. Two baseline records have author `BOR=NE` and GEO `response=UNK`; under the inherited endpoint rule, at most 49 baseline records have an evaluable BOR category before assay QC, exclusion, overlap, and exposure checks. No expression values were examined to support this proposal. [Identity review](A_DAV_RIAZ_IDENTITY_REVIEW_20261026.md), [clinical review](A_DAV_RIAZ_CLINICAL_REVIEW_20261026.md), [decisions record](A_DAV_RIAZ_DECISIONS_20261026.md).

## Proposed rule set

### Source and identity

| Check | PASS | BLOCK | QUARANTINE |
| --- | --- | --- | --- |
| Source object | The matrix and sample annotation each resolve to the already pinned source object, with complete-byte hash, version, and retrieval/provenance receipt matching the selected representation. | Missing object identity, incomplete hash, changed bytes without a new object/version, or undocumented processing prevents matrix validation. | A replacement or alternate object is preserved under its own identity while source equivalence or representation suitability is unresolved; do not substitute it silently. |
| Sample-to-assay join | Every selected baseline matrix column resolves to exactly one source sample and one assay record; the assay resolves to exactly one specimen; the specimen resolves to exactly one patient. Source IDs and joins agree with the accepted field map and evidence pointers. | Zero or multiple joins, a source-label conflict affecting a selected baseline join, or a selected baseline column without an assay/specimen/patient chain blocks that record and the matrix build. | Preserve affected baseline source records and conflict evidence outside the analytical matrix pending reviewer resolution; never repair identity by shared code, row order, or a similar title. |
| Baseline timing | Only source-labelled pretreatment (`Pre`) specimens are candidates for this branch. Do not infer an individual collection day from the protocol window. | An `On` specimen, unknown Pre/On status, or conflicting timepoint label is ineligible for the baseline matrix. | Keep unresolved timing records in the source registry and exclude them from this baseline candidate set until evidence resolves timing. |
| Full header inventory versus branch columns | Separately inventory the complete source object's sample header (the source is reported to contain 109 RNA-seq columns) and reconcile each header key to the source sample inventory/header record only. This inventory step does not require clinical patient, specimen, assay, or author-table identity resolution for unselected on-treatment columns. Then select the 51 baseline (`Pre`) columns for the baseline branch using the accepted map and apply patient/assay joins to those selected columns. The other 58 (`On`) columns remain part of source-header accounting and are not required baseline matrix columns. | A duplicate/malformed header or a true gap between a source-object header key and its expected source sample inventory blocks validation of the affected object/header. Missingness is judged against the expected full-source header, not by asking the baseline matrix to contain `On` columns. | Preserve unresolved on-treatment identity items with their source evidence. Their exclusion from the baseline selection is not a missing-map failure. |
| Patient multiplicity | A candidate baseline selection has one biological specimen per patient, with all assay representations for that specimen kept as linked measurements. The current source review reports one baseline specimen for each of the 51 baseline patient joins. | A missing baseline candidate or an assay/specimen mismatch blocks that patient's row. More than one distinct baseline biological specimen for a patient blocks automatic selection. | Hold all of that patient's baseline candidates until a source-supported, outcome-blind resolution rule is available. Preserve all candidates and reasons; do not ask for or invent a hypothetical tie-break while the current records contain one each. Two measurement representations of the same specimen are not duplicate biological specimens. |

Apply identity validation in two layers: reconcile the complete source header (109 sample columns as documented) against the source sample inventory, then verify that the baseline selection contains the expected 51 `Pre` columns and no `On` columns. The unselected 58 `On` columns are not omissions from the baseline branch. Keep all 51 linked pretreatment records in metadata/source accounting while candidate eligibility is resolved; do not describe 51 as a passed assay count or final matrix size. The reviewed unmatched author rows, duplicate patient/visit record, and GEO/cBioPortal two-specimen difference concern on-treatment material and do not justify baseline removals. They remain relevant to longitudinal work. [Identity review](A_DAV_RIAZ_IDENTITY_REVIEW_20261026.md), [source inventory](A_DAV_REAL_INGESTION_SOURCES_01.md).

### Endpoint and response eligibility

Preserve author BOR and GEO `response` as separate source assertions. Use author BOR for the declared endpoint; retain GEO as corroboration. Proposed categorical handling is CR/PR = objective responder, SD/PD = objective nonresponder, NE/unknown = not evaluable, following the frozen ontology. The baseline NE/UNK pairs remain retained metadata records and are excluded from ORR-evaluable membership; never recode NE as PD, nonresponse, or a negative ORR label. Any other unresolved BOR conflict blocks endpoint eligibility for the affected record while preserving its source and assay QC state. The outcome flag is not a technical assay-QC failure.

Consequently, 49 is only an upper bound on outcome-evaluable baseline records before QC and other gates, not an approved QC denominator or a promised final N. The paper reports a 45-patient baseline transcriptomic analysis; that number does not define this branch's inclusion rule. [Frozen endpoint ontology](../../specs/A_DATA_ACQUISITION_VALIDATION/ENDPOINT_ONTOLOGY.md), [Riaz clinical review](A_DAV_RIAZ_CLINICAL_REVIEW_20261026.md).

### Matrix structure and feature identity

These checks are proposed to run only after the reviewer selects one measurement representation and its source object. They are marked **PROPOSED_NOT_RUN** because no expression matrix values or numerical summaries were read or computed for this note.

| Check | Proposed disposition |
| --- | --- |
| Matrix dimensions and parsing | **PASS** only if the complete matrix parses under its documented delimiter/encoding and its row and column dimensions agree with the source object's declared matrix/header. **BLOCK** malformed/truncated input or unexplained dimension/header disagreement. |
| Selected baseline columns | **PASS** only if selected baseline column IDs are unique and each maps one-to-one to the selected assay/specimen. **BLOCK** duplicate selected columns or an unresolved/missing sample mapping. Do not merge replicate columns. The remaining source-header columns are validated under the separate full-header inventory rule; they are not required in the baseline matrix. |
| Feature rows | **PASS** only if feature IDs are present, unique at the declared feature grain, and match the source annotation/build and the selected representation. **BLOCK** duplicate/blank IDs or incompatible/mixed feature systems until an explicit annotation/collapse rule is approved. Preserve unmapped rows as recorded coverage outcomes; do not invent identifiers or convert missing genes to zero. |
| Numeric parse and missingness | **PASS** only if all retained cells parse as numeric and meet the selected representation's documented missingness rule. **BLOCK** non-numeric cells, infinities/NaNs, or missing-value encoding that cannot be distinguished from a measured zero. Do not impute missing values or silently drop affected samples/features. |
| Continuous-value validity | For either selected continuous representation, **PASS** only when all retained cells parse as finite, nonnegative numeric values and the producer documents the declared scale. **BLOCK** nonnumeric, nonfinite, negative, or scale-conflicting values. Do not impose integer-likeness, round values, or convert one representation to the other. |
| Scale and transformation | **PASS** only when the unit, gene/transcript grain, normalization, transform, genome build, and annotation can be tied to the selected source representation. **BLOCK** undocumented or mixed scales, unexplained prior normalization, or evidence inconsistent with the source description. Magnitude heuristics may flag a question but cannot assign a unit or override provenance. |
| Repeated/suspicious profiles | Flag exact duplicate or suspiciously identical profiles for identity/technical review. **QUARANTINE** affected columns while source-level replicate/aliquot status is checked. Do not infer a replicate or remove a sample from expression similarity alone. |

No read-depth, library-size, RIN, mapping-rate, contamination, or feature-coverage threshold is proposed: no reviewed source provides a supported numerical cutoff for this branch. The article describes RNA-seq processing on hg19 and an author FPKM representation; the pinned Table S6A script uses a separate author count matrix for its published differential-expression analysis, which is not a candidate representation in this baseline proposal. The two retained candidate measurement representations are: (1) author-deposited `GSE91061_BMS038109Sample.hg19KnownGene.fpkm.csv.gz` (hg19/knownGene, Entrez IDs, FPKM), with source version and complete SHA-256 pinned; its header was previously inspected from a compressed prefix and reported to match all 109 GEO sample titles; and (2) official NCBI `GSE91061_norm_counts_TPM_GRCh38.p13_NCBI.tsv.gz` (GRCh38.p13, NCBI TPM), also retrieved with source version and complete SHA-256 pinned; its 109 GSM-keyed columns were previously seen in a prefix. The authorized nine-object retrieval completed with 28,667,384 bytes total, including both expression objects, and all nine complete hashes are in the field map/fetch plan. Full-object retrieval and hashing do not mean numeric matrix validation has occurred. The NCBI TPM processing method remains unverified. These are distinct representations, not interchangeable versions: do not convert between them. The author FPKM offers direct author processing provenance; the NCBI TPM offers first-party, GSM-keyed coverage and a newer genome build, with processing details still unresolved. [Riaz RNA-seq Methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC5685550/#sec3), [pinned author `TableS6.A.R`](https://raw.githubusercontent.com/riazn/bms038_analysis/137111c38a32f8626ee6a436e14ac667bd31b1e7/rnaseq/TableS6.A.R), [real-source retrieval record](../handoff/20261025/HANDOFF.md#real-source-run), [pinned field map and object hashes](../../tools/a_dav/field_maps/riaz_gse91061.json).

### Outcome-blind exclusions and flags

Technical QC must be performed without viewing BOR, GEO response, response-group labels, or response-associated analysis results. The operator may use specimen identity, collection timing, source provenance, assay-processing metadata, matrix structure, feature identifiers, and numeric validity. Store QC status/reason separately from endpoint eligibility so that an unevaluable endpoint does not masquerade as an assay failure.

Retain the paper's PCA outlier statement and the script's four named baseline removals as **historical analysis flags only**. Neither is an automatic exclusion in this proposed baseline QC policy. The article describes one manually identified PCA outlier; the author script explicitly removes four named pretreatment samples but gives no rationale in those lines. The paper and script thus document different exclusion statements, and the reviewed evidence does not resolve their relationship or reproduce the full script matrix intersection. Do not use either to remove a sample from the proposed branch, and do not tune rules to yield N=45. If exact Table S6A reproduction is later authorized, it needs its own reconciled population and methods decision. [Riaz clinical review](A_DAV_RIAZ_CLINICAL_REVIEW_20261026.md), [article RNA-seq Methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC5685550/#sec3), [pinned Table S6A script, lines 80–121](https://github.com/riazn/bms038_analysis/blob/137111c38a32f8626ee6a436e14ac667bd31b1e7/rnaseq/TableS6.A.R#L80-L121).

## Missing raw-read QC and remaining choices

The reviewed evidence establishes that the paper's processing began from FASTQ, but this proposal does not establish availability, identity, or completeness of matched FASTQ files for these baseline records. Until a raw-read object and source-to-specimen link are separately evidenced, read-level quality metrics are **unavailable**, not failed and not assumed. This limits suitability claims for any requirement that depends on read-level QC. It does not justify inventing thresholds or running a raw reprocessing route; the processed-data-first policy would require a separately justified, approved amendment before such reprocessing.

Before implementation, the reviewer should approve two decisions that affect executable rules:

1. **QC rule approval:** approve the outcome-blind structural/identity, numeric-validity, hold/quarantine, and historical-flag rules above. No additional numeric thresholds are proposed, so no threshold value requires a separate decision.
2. **Representation selection:** choose author hg19 FPKM or official NCBI GRCh38.p13 TPM for this branch. Both exact full objects have already been retrieved and their complete SHA-256 values pinned; no new retrieval or conversion is implied. Selection does not itself certify matrix structure, feature universe, numeric validity, or downstream suitability. Validate the complete header and matrix structure from the retained full object. The author FPKM has previous 109-title header evidence; the NCBI TPM has previous 109-GSM-column prefix evidence and unresolved pipeline details.

No separate tie-rule decision is needed now: current evidence has one baseline biological specimen per each of the 51 baseline patient joins. If a later validation discovers multiple distinct baseline specimens for a patient, hold that patient pending evidence-based outcome-blind resolution. Alternative assay representations of one specimen remain linked assays, not additional biological specimens.

After those decisions, an implementation can validate the selected object's complete 109-column source header from the retained full object separately from its 51 selected baseline columns, then run the structural and numeric checks and return counts, reasons, and a receipt. Until then all numerical matrix checks in this proposal remain **PROPOSED_NOT_RUN**. Missing read-level QC metrics remain a stated suitability limitation if no supported processed-object QC evidence resolves it; they do not create an unapproved requirement for thresholds or raw-data reprocessing. No new packet or review artifact is required by this note; its approval can be captured in the existing Riaz reviewer worksheet/decision process.
