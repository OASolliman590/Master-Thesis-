## 1. GEO formats

**Directory layout (NCBI FTP README, last updated 2019-07-16).** [README](https://ftp.ncbi.nlm.nih.gov/geo/README.txt)
- Record directories are grouped into range directories "created by replacing the three last digits of the accession with letters 'nnn'". Series records have subdirectories `matrix/`, `miniml/`, `soft/` and `suppl/`.
- The README's file definitions:
  - `matrix/GSExxx_series_matrix.txt.gz` (or `GSExxx-GPLxxx_series_matrix.txt.gz` for multi-platform series) is a "tab-delimited value-matrix table … headed by Sample and Series metadata", with SOFT attribute labels.
  - `miniml/GSExxx_family.xml.tgz` holds the MINiML for all GPL and GSM records of the series.
  - `soft/GSExxx_family.soft.gz` holds the SOFT for all GPL and GSM records of the series.
- The README also says family SOFT and MINiML "generally contain the same data, just organized differently".
- The same tree is served over HTTPS:
  - `https://ftp.ncbi.nlm.nih.gov/geo/series/GSE91nnn/GSE91061/{soft,matrix,miniml,suppl}/`
  - **NEW, not in the README:** `https://ftp.ncbi.nlm.nih.gov/geo/rnaseq_counts/GSE91nnn/` and `/geo/rnaseq_counts/annot/`. The `annot/` directory holds `Human.GRCh38.p13.annot.tsv.gz` (4.2 MB, 2022-11-08).

**Family SOFT line grammar, as observed in NCBI-generated `GSE91061_family.soft.gz`.** The doc page `soft.html` is UNVERIFIED (reCAPTCHA); the README points to `soft2.html#SOFTformat`. The file is line-based UTF-8/ASCII with 5,393 lines.
- `^ENTITY = ACCESSION` opens a block. The blocks seen are `^DATABASE = GeoMiame`, `^SERIES = GSE91061`, `^PLATFORM = GPL9052`, and 109 × `^SAMPLE = GSMnnnnnnn`. A sample block runs until the next `^` line.
- `!Entity_attribute = value` lines carry attributes. Repeated attributes appear as repeated lines; for example, each sample has 3 × `!Sample_characteristics_ch1` and 2 × `!Sample_relation`.
- `!Sample_characteristics_ch1 = <tag>: <value>` is a **free-text** `tag: value` pair, split on the first `": "`. The tag can contain spaces and parentheses (`visit (pre or on treatment)`).
- `!Sample_relation = BioSample: https://www.ncbi.nlm.nih.gov/biosample/SAMN…` and `!Sample_relation = SRA: https://www.ncbi.nlm.nih.gov/sra?term=SRX…` give the BioSample and SRA links.
- The series block has `!Series_relation = BioProject: …/PRJNA356761` and `!Series_relation = SRA: …SRP094781`.
- GSE91061 has no `#` column-description or `!sample_table_begin` lines, because every sample has `!Sample_data_row_count = 0` (RNA-seq with no GSM data table). Another series could carry tables; that grammar is UNVERIFIED for this note.
- Dates per record are `!Series_last_update_date = May 15 2019` and `!Sample_last_update_date = May 15 2019` (all 109), plus `_status` ("Public on Jan 23 2018") and `_submission_date` ("Dec 08 2016"). The date format is `Mon DD YYYY`. **There is no revision number and no file-generation timestamp inside the SOFT.**

**Series matrix layout (observed).**
- Lines start with `!Series_*`, then a blank line, then one `!Sample_*` row per attribute, with tab-separated, double-quoted values, one column per GSM.
- Repeated attributes become **repeated rows**. GSE91061 has 3 `!Sample_characteristics_ch1` rows and 2 `!Sample_relation` rows. Row *k* is "the k-th characteristic of each sample", not a fixed key, so in heterogeneous series the same row can hold different tags.
- Then come `!series_matrix_table_begin`, a `"ID_REF"` row with 109 GSM columns and no data rows, and `!series_matrix_table_end`.
- The matrix omits the platform block and some sample fields; for example, there is no `!Sample_series_id` row and no `!Sample_library_*` duplication check. Verify which fields an adapter needs.

**MINiML (observed).**
- The root element is `<MINiML xmlns="http://www.ncbi.nlm.nih.gov/geo/info/MINiML" xsi:schemaLocation="http://www.ncbi.nlm.nih.gov/geo/info/MINiML http://www.ncbi.nlm.nih.gov/geo/info/MINiML.xsd" version="0.5.0">`. The XSD URL is behind reCAPTCHA, so the XSD content is UNVERIFIED.
- Characteristics are structured: `<Characteristics tag="response">PD</Characteristics>`, with whitespace and newlines around the value that must be stripped.
- Relations are `<Relation type="BioSample|SRA|BioProject" target="…"/>`.
- Dates are ISO: `<Last-Update-Date>2019-05-15</Last-Update-Date>`, along with `Release-Date` and `Submission-Date`.

**`acc.cgi` text endpoint.**
- `https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE91061&targ=gsm&form=text&view=brief` returned 321,046 B of plain SOFT-style `!Sample_*` lines for all 109 GSM. It has no `^SERIES` or `^PLATFORM` block.
- It is generated dynamically, carries no `Last-Modified`, and is not an archived object. It is fine for probes but not as the pinned object.
- HTML `acc.cgi` views, for example `acc=<a GSM>` without `form=text`, returned reCAPTCHA. Adapters must detect HTML or challenge bodies; REPORT §8 already found reCAPTCHA HTML saved as `.xlsx`.

**E-utilities.**
- `esearch db=gds term=GSE91061[ACCN] AND gse[ETYP]` resolves to UID 200091061.
- `esummary` gives `n_samples 109`, `gpl 9052`, `bioproject PRJNA356761`, `pubmedids [29033130]`, SRA `SRP094781`, and the FTP link.
- The NCBI rate limit without an API key (commonly cited as 3 requests/s) is UNVERIFIED, because the book page is blocked.

**Recommendation: pin `soft/GSE91061_family.soft.gz`.**
1. It is a **static archived object** with `Last-Modified` and `Content-Length`.
2. Its gzip header has `mtime=0` and no `FNAME`, so the compressed bytes are reproducible across NCBI regenerations when the content is unchanged. This was shown empirically: the September and October SHA-256 values are identical despite an Aug-2026 regeneration.
3. It contains the series, platform and all samples in one file, including `last_update_date` per record.
4. Its grammar is line-trivial, and the existing `audit_metadata.py` already parses it.

By contrast:
- MINiML `.tgz` has a gzip mtime and a tar member mtime of 2026-08-09 05:05:23, so archive bytes change on every regeneration. If you use it, hash the inner XML; that hash is `135fb346…` today.
- The series matrix positional rows are fragile.
- `acc.cgi` is dynamic.

Record two hashes:
- the SHA-256 of the `.gz` bytes (identity of the retrieved object);
- the SHA-256 of the decompressed text, `26b7a232…`, which detects content drift independently of compression.

Use `!Series_last_update_date` together with the per-sample `last_update_date` as the version field.

## 4. GitHub pinned-commit retrieval

**Docs.** [Repository contents API](https://docs.github.com/en/rest/repos/contents?apiVersion=2022-11-28)
- `ref` is "The name of the commit/branch/tag. Default: the repository's default branch". Passing the full SHA pins it.
- Files ≤1 MB get all features. For 1–100 MB, only the `raw` or `object` media types work (`application/vnd.github.raw+json`). Above 100 MB is unsupported.
- Directory listings are capped at 1,000 entries; use the Git Trees API beyond that.
- The `sha` returned is the **git blob SHA-1**, i.e. `sha1("blob <len>\0" + bytes)`, not SHA-256. This was verified locally: computed blob SHA-1 values equal the API `sha` for all four files fetched.
- Raw retrieval at a commit uses `https://raw.githubusercontent.com/<owner>/<repo>/<sha>/<path>`. Its `ETag` (e.g. `"0d3ca50b…"` for the clinical CSV) is **not** the SHA-256 of the content (`a70ae5a0…`). Compute SHA-256 yourself.

**Rate limits.** [GitHub REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api?apiVersion=2022-11-28)
- Unauthenticated: 60 requests/hour per IP, reported by the `x-ratelimit-limit`, `-remaining`, `-used`, `-reset` and `-resource` headers. This was observed live: limit 60.
- On a secondary limit, honour `retry-after`, otherwise wait ≥1 min, with exponential backoff.
- raw.githubusercontent.com is not counted against the REST core budget (observed; the documented policy is UNVERIFIED).

### Minimal adapter shapes

- **`geo_soft_adapter`**
  - Input: the pinned SOFT bytes plus their recorded hashes.
  - Parse: split on `^SAMPLE = `. Take `!Sample_title`, `!Sample_geo_accession`, `!Sample_last_update_date`, and each `!Sample_characteristics_ch1` split on the first `": "` into (tag, value). Keep the raw line too. Extract `!Sample_relation` by prefix (`BioSample:` gives SAMN, `SRA:` gives SRX).
  - Emit one row per GSM with columns `gsm, title, title_patient, title_visit, title_specimen, raw characteristics (JSON), samn, srx, last_update`.
  - Assert: 109 rows; Pre 51; each GSM has exactly one SAMN and one SRX; `title` unique; (patient, visit) duplicates reported, not deduplicated.
  - This is a port of `audit_metadata.py` without its `E:/` path.
- **`ena_run_adapter`**: emit `run, srx, samn, srs, gsm(sample_alias), title, last_updated`. Assert a 1:1:1 mapping and the equality with GEO on (gsm, title, samn, srx).
- **`author_table_adapter`**
  - Read with `csv.reader`, by **position**. Assert the exact header list.
  - Handle CRLF in the clinical file. Strip `.bam` and apply REPORT's terminal `.digit→-digit` rule, logging every rewrite.
  - Join to GEO on the specimen code first, then compare patient codes. A patient-code disagreement becomes a conflict row.
  - Emit raw `BOR` unchanged, plus `Cohort`.
  - Never map `myBOR`, `myBOR2`, `myBOR3`, LB/NB or `IBOR` to ORR silently.
- **`cbioportal_crosscheck`, `iatlas_crosscheck`**
  - Map keys: `Pt<n>_<pre|on>` for cBioPortal; for iAtlas, `-p<NNN>-ar-<last4 SRR>` via ENA.
  - Emit a per-specimen disagreement report against author BOR and GEO response. "Missing in cross-check" is its own status, not a disagreement.

### Pitfalls

1. **Free-text characteristics.** In SOFT the `tag: value` pair is submitter text; tags contain spaces and parentheses. Series-matrix characteristic rows are positional, not keyed. Prefer MINiML `tag=` or SOFT parsed per line. Normalise whitespace, and keep the raw string.
2. **CR and PR merged as `PRCR`, NE as `UNK` in GEO.** GEO gives PRCR 23 and UNK 4 across all samples. CR/PR can be split only from author `BOR` (column 9). cBioPortal and iAtlas present the CR/PR split, but derived from the same author source; it is not independent confirmation.
3. **NE vs UNK vs NA vs missing.** The same 2 baseline patients appear as:
   - author `BOR=NE`
   - GEO `UNK`
   - sample-table column 10 `NA`
   - cBioPortal: no RESPONSE value
   - iAtlas: `na_response`
   - author `myBOR`: **PD**, because NE is folded into PD

   Treat these as one "not evaluable / unknown" class only by an explicit, frozen rule (a human decision per the appraisal).
4. **Title-encoded patient IDs.**
   - Patient identity exists only inside `!Sample_title` (GEO and ENA), in `Pt<n>_<visit>` (cBioPortal), or as `p<NNN>` (iAtlas). Each source uses its own case and zero-padding.
   - `Pt<n>` codes are study-local and collide across studies (REPORT §5: 18 overlaps with Hugo). Always namespace them, e.g. `CA209-038/Riaz2017:Pt<n>`.
5. **Sample-count disagreements.**
   - GEO has 109 samples and 65 patients. The author sample table has 108 rows and 64 patients. cBioPortal and iAtlas have 107 samples and 64 patients.
   - The causes found: Pt109 has 2 On specimens in GEO, 1 in the author table and 0 in cBioPortal/iAtlas. The Pt68 (GEO) vs Pt72 or `Pt7_Pre` BAM (author) code conflict is on one On specimen.
   - Separately, the paper's baseline RNA N is 45 (REPORT §3). None of these are baseline-relevant except as join hazards.
6. **Duplicate `Response` header** in the author sample table (REPORT §2), and a `PopCateg` value that contradicts `PreOn` on one row. Treat `PreOn` as the visit field and report `PopCateg` mismatches.
7. **Bot challenges and HTML-as-data.** NCBI HTML pages and docs currently return reCAPTCHA. Adapters must check `Content-Type` and magic bytes (gzip `1f8b`) and refuse HTML bodies. Never solve challenges.
8. **Hash drift without content drift.** MINiML `.tgz` changes on each regeneration. Live API JSON has no version, so canonicalise before hashing and record retrieval time plus `/api/info`.
9. **Scale mismatches.**
   - GEO author file: hg19 knownGene FPKM (DESeq2 robust).
   - NCBI rnaseq_counts: GRCh38.p13 TPM. Its pipeline details are UNVERIFIED (doc page blocked).
   - cBioPortal: *log* TPM, hg38.
   - Do not mix them, and freeze one per branch, as PROCESSED_DATA_POLICY requires per the provenance note.
10. **Licence layering.** Author repo has no licence. cBioPortal is ODbL (share-alike). iAtlas terms unknown. GEO terms UNVERIFIED. Commit only hashes, locators and aggregate counts.
