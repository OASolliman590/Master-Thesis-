# Proposed A-LONG decisions N12 and N13

**Status: PROPOSED.** This note records source-backed options and explicit model choices for review. It does not sign a decision, admit a real pair, fill a frozen value, or close a gate. The real A-P2 rebuild remains deferred and unrun.

## N12 — source-specific pairing and timing

Use explicit source-specific timing categories, day origins, windows, baseline hierarchies, index episodes, exposure definitions, and assay/compartment qualifications. The code blocks pairing when any required source rule is unsigned or unknown.

- For Riaz et al., the reported collection schedule places baseline sampling 1–7 days before the first nivolumab dose and scheduled on-treatment sampling 23–29 days after treatment start, with an intended same-site sample. These are schedule intervals, not exact observed specimen days. Preserve the raw day and precision; do not assign every on-treatment specimen day 29. [Riaz et al., Cell (2017), STAR Methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC5685550/).
- For Gide et al., PRE is before therapy and EDT is scheduled 7–14 days after treatment begins. Run-level days and the proposed 14-run crosswalk remain unverified and unaccepted. Keep the crosswalk disabled until the user explicitly accepts a specific mapping in a record. [Gide et al., Cancer Cell (2019), STAR Methods](https://doi.org/10.1016/j.ccell.2019.01.003).
- For GSE168204, the cited publication combines earlier and newly generated MGH datasets. Do not assign combined counts to GSE168204 alone. The deposited day-field origin remains unknown, so exact-day pairing stays blocked until source-specific evidence resolves it. [Du et al., Nature Communications (2021)](https://doi.org/10.1038/s41467-021-26299-4).

Require study, patient, specimen, assay, index-episode, and exposure consistency. Require an explicit source-specific baseline hierarchy. Keep exact day, raw category, and precision as separate values. A verified categorical PRE/ON window can be used when exact day is missing, while exact day remains unknown. A contradictory exact day and category requires adjudication. Exclude prior-treatment baselines, progression, regimen changes, and after-stop collections from scheduled on-treatment windows unless a separately authorized contrast names the exception.

Retain every candidate and exclusion reason, technical-replicate count scoped by study/patient/specimen, missing-follow-up patient, selected window, same-lesion count, platform/unit count, source locator/confidence, raw PRE/ON day and precision, day-to-target distance, annotation/comparability identities, endpoint/exposure/episode bindings, and admission receipts. Select the eligible baseline specimen by the declared source hierarchy first. Then select its follow-up by source-specific timing relevance, compatible qualified assay and compartment, an admitted same-lesion preference, and an opaque stable tie-breaker. Never average incompatible units or count technical assays as people. Canonical sorting must keep pair identifiers and product hashes invariant to row permutation.

The outcome-free product reports structural candidates and attrition only. Endpoint-evaluable counts are unavailable, not zero. It never reads or joins response, survival, benefit, or clinical endpoint values. Real inputs must provide explicit selected columns at the read boundary; the pair path does not load ingestion packets or whole clinical tables.

## N13 — numerical methods and synthesis

The code implements these explicit candidate method IDs. Production fitting remains blocked until the user accepts N13 and supplies its policy values.

- **Primary two-timepoint contrast:** compute d = on − pre and fit d ~ response + prespecified_covariates. Report the direct R-minus-NR change estimate, standard error, two-sided interval, residual degrees of freedom, design rank, group counts, and each non-estimability reason. Baseline expression is not a primary covariate.
- **ANCOVA sensitivity:** fit on ~ response + pre + prespecified_covariates. Label its coefficient as a conditional-on-baseline association; do not call it the primary change contrast.
- **Repeated windows:** fit expression ~ response * window + (1 | patient), and report each planned R-minus-NR interaction against the declared baseline window. The bound N13 policy must explicitly select `complete_declared_windows` or `available_observations`; the implementation does not choose a missing-window rule. Apply support minima to each contrast, and retain contrast-specific patient and observation counts separately from total fitted observations. Require valid degrees of freedom, full rank, convergence, and a nonsingular fit. The proposed implementation uses lme4 2.1-0 and lmerTest 3.2-1 with Satterthwaite degrees of freedom; pbkrtest 0.5.5 is checked in the bridge. emmeans is not used. [lme4 documentation](https://cran.r-project.org/web/packages/lme4/index.html), [lmerTest documentation](https://cran.r-project.org/web/packages/lmerTest/index.html).
- **Randomized arms:** keep an admitted within-study ICI-only versus combination change contrast separate from the observational response interaction. Require explicit randomization verification and a comparative-estimand record. Do not compare arms by comparing significance.
- **Synthesis:** retain one effect per study within a declared endpoint, regimen, window, assay, feature method, analysis method, and effect-scale family. Use the A-META REML/modified Knapp–Hartung convention (`metafor::rma.uni(method = "REML", test = "adhoc")`), including its variance floor; ordinary KH is not the reported method. Keep k=1 as its study effect; label k=2–3 tentative and suppress prediction intervals; require the explicitly accepted minimum k (the current proposal is 4) for the pooled label and prediction interval. Multi-study independence requires a complete pairwise receipt table binding both studies, both source-family identities, an explicit overlap status, and each receipt hash. Missing, overlapping, or unresolved relations exclude the family from pooling even when patient-set hashes differ. Do not relabel change betas as standardized mean differences. [metafor rma.uni reference](https://wviechtb.github.io/metafor/reference/rma.uni.html), [metafor recommended practices](https://wviechtb.github.io/metafor/reference/misc-recs.html), [prediction interval reference](https://wviechtb.github.io/metafor/reference/predict.rma.html).
- **Multiplicity:** apply Holm only across the predeclared panel family within the same synthesis family. Apply BH at 10% to the exploratory M5/M6 gene family. Missing planned members enter the declared denominator as p=1 for adjustment, while their reported p and adjusted p remain missing. Do not apply a manuscript-wide FDR.

The currently checked minimum-support values in invented test policies are fixture inputs, not production thresholds. N13 must supply explicit production support thresholds, covariates, confidence level, repeated-window set, FDR scope, and minimum synthesis k. No count-derived precision model is offered; a future count route must use the supported voom/dream setup. No negative-binomial route is offered. Missing biopsy is never zero or nonresponse, and no model-based missingness cure is included.

The paired two-timepoint route can emit same-lesion, exact-day, and tighter-timing sensitivity rows only when the exact N13 policy selects them. Tighter timing requires a positive, source-specific maximum deviation from the declared target day; the code chooses no universal cutoff. Exact-day sensitivity requires known exact PRE and ON days. These are separate method identities; they do not replace the central change contrast. Unknown days never qualify. Repeated-window and randomized-arm routes refuse these pair-specific sensitivity modes.

The feature-join boundary requires an explicitly mapped `endpoint_id` and response column and verifies every endpoint row against the endpoint identity in the bound policy. Missing endpoint rows stay missing. Model `longitudinal_support.tsv` separates pairing/model-input counts from per-effect rows, carries each sensitivity's pair, patient, and observation support plus its status/reason, and has no patient identifiers. Only repeated-window effects carry the `one_way_longitudinal_corroboration` role; the paired primary and sensitivity effects retain their own roles.

The default-locked Python CLI/API exposes `pair-to-analysis`, `two-timepoint`, `ancova`, `repeated`, `randomized-arm`, and `synthesize`, in addition to outcome-free pairing and invented demonstrations. Each N13 CLI route requires the future explicit `--allow-outcomes` option; the released Python APIs default to `allow_outcomes=False` and require `allow_outcomes=True`. Direct R independently checks the real-classified N13 boundary's explicit true value before reading outcome payloads. N12 outcome-free pairing remains available under its source and policy record without this outcome opt-in. The flag and API argument do not authorize a route: each still requires an exact scoped user-release record whose hash binds its decision identity/path/hash, operation, policy, input manifest, source files, cohort set, and named permitted fields. A status string, boolean, or arbitrary reference does not act as a signature. Synthesis requires separate named effects and pairwise overlap-receipt sources. The concrete future command templates and private product schemas are in [tools/a1/README.md](../../tools/a1/README.md).
